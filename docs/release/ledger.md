### Ledger procedure

1. Each row is one capability. Its ID is stable; do not renumber. Add new rows
   at the end of the relevant area.
2. A row is accepted for launch only when **every** applicable column holds
   evidence for the release candidate: code status, automated evidence on a
   green hosted CI run, the deployed SHA, live-provider evidence where a
   provider is involved, and a recorded decision.
3. `pending` means no evidence exists yet. `n/a` means the column does not apply
   (for example, no external provider is involved). Never write "done" without
   a link or a receipt reference.
4. Evidence links point to durable, access-controlled storage. Do not paste
   customer content, tokens, account IDs, email addresses or provider payloads
   into this file. Keep evidence outside the Tailwind scan paths (`app/`,
   `components/`, `lib/`).
5. Owners are roles, not people. Appointing a person to a role is a decision for
   the product owner and is recorded in the decision log.
6. Update the ledger in the same pull request as the change that alters a row.

### Code status vocabulary

| Status                 | Meaning                                                                                                                            |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| `verified (automated)` | Implemented; automated tests cover the behaviour and the inventory found no gap. Deployed and live evidence may still be required. |
| `awaiting evidence`    | Implemented, but automated, deployed or live evidence is incomplete, or a known gap is listed under residual risk.                 |
| `unavailable`          | Present in the repository but not currently runnable or relied on (blocked CI, dead code).                                         |
| `retired — remove`     | Calls a Google API that Google has discontinued. Must be removed before launch.                                                    |
| `absent`               | Not built.                                                                                                                         |
| `deferred`             | Not built, and proposed to stay out of the launch scope (needs a decision).                                                        |

### Invalidation rule

Evidence is bound to a SHA. When a source or configuration change lands after
evidence was recorded, the pull request that makes the change names which
evidence it invalidates, and the affected rows return to `pending` for the
deployed SHA and any rerun column. As a minimum:

| --------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |

| `supabase/migrations/`                                                                                                            | Migrations job (clean and upgrade), integration suite, production ledger comparison (CI-07), restore drill if the migration is destructive |
