## Units and labels

| Symbol            | Meaning                                                                                                                                        |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| **Req**           | One HTTP request to the app: a document, an RSC flight (`?_rsc`) or `/api/*`. Static JS/CSS is not counted.                                    |
| **Tx**            | One Postgres transaction (`BEGIN … COMMIT`) from the pool (`getDatabase().begin` / `withTenant`).                                              |
| **S**             | SQL statements inside a Tx, not counting BEGIN/COMMIT. `withTenant` always adds one `set_config` statement (`lib/server/db.ts:121-129`).       |
| **Ws**            | One `UPDATE app_session SET last_seen_at …` (`lib/server/session.ts:217-229`).                                                                 |
| **G**             | One outbound Google API call.                                                                                                                  |
| **N / L / C / F** | N = infinite-list pages loaded in the inbox (50 rows/page) · L = visible locations · C = visible clients · F = hidden→visible tab transitions. |

Every count is labelled:

- **CONFIRMED:** traced in code or library source.
- **ESTIMATED:** derived from code, but with a conditional branch or a statement count I did not walk line by line.
- **PLAUSIBLE:** follows from library semantics but was not observed at runtime.

## 2. Selecting a different review (selection change)

**The Next 16 question: does the dashboard layout re-run? No. CONFIRMED in Next 16.3.8 source.**

- **Client side** (`node_modules/next/dist/client/components/router-reducer/ppr-navigations.js:157-177`): a shared segment's existing CacheNode is reused (`needsDynamicRequest = false`). Two cases are excluded: the leaf of a same-page navigation, and `segmentMatchKind === 2` ("a search-param-only change is treated as a refresh of the page segment"). `createDynamicRequestTree` (`:454-475`) sets the `'refetch'` marker on the top-most segment that needs data, which is `__PAGE__`.
- **Server side** (`server/app-render/walk-tree-with-flight-router-state.js:55-61`): rendering starts at the first segment whose key does not match, or that is marked `refetch`. The `(dashboard)` and `inbox` segments match, so **`DashboardLayout` is not executed**. Only `InboxPage` (plus head/metadata) is.
- `staleTimes.dynamic` keeps its default of 0, so revisiting a previously selected id does not hit the BFCache either.
- This **confirms** W5-01's premise for the page segment, and **clears** the layout. The five layout loaders do **not** re-run per click.

The selected row can then drop out of the list and the scroll position is lost. To confirm, scroll past row 50, click a row, and watch the row count. The fix in multiplier M2 removes this effect, along with the RSC round trip.

## 4. Idle, visible inbox tab for 10 minutes

TanStack v5 gates interval ticks on `focusManager.isFocused()`, which only means `visibilityState !== "hidden"` (`query-core/.../queryObserver.js:214-217`, `focusManager.js:55-60`, `visibilitychange` listener). A hidden tab does **not** poll. A "window-focus" refetch fires on hidden→visible, not on app switching. CONFIRMED.

Shell observers mount in the same commit, so their timers align and each key polls once a minute (R2-V1 correction to W1 F10). The reconnect banner, the only dynamically imported poller, mounts only when a connection is broken (`reconnect-banner-gate.tsx:30-42`).
